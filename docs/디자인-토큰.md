| | 팔레트 | 정의 위치 |
|---|---|---|
| **슬라이드(.pptx)** | 네이비 `#1E2761` + 앰버 `#F2A900` | `core/deck_builder.py` `_HEX` |

## 1. 슬라이드 색 — 네이비 단일 계조 + 앰버 1점

무지개 로테이션(navy/teal/blue/plum/green)은 폐기했다. **순서가 있는 값은 단일 색조의
계조로**, 강조는 앰버 한 점으로만 낸다.

| 토큰 | HEX | 용도 |
|---|---|---|
| `navy` | `#1E2761` | 제목 · 주요 채움 (흰 글씨 OK) |
| `navy_75` | `#565D88` | 계조 2단계 |
| `navy_55` | `#8388A8` | 계조 3단계 · 키커 · 캡션 |
| `navy_30` | `#BBBED0` | 비활성 · 대형 연번 |
| `navy_12` | `#E4E5EC` | 카드 헤어라인 링 · 러닝 구분선 |
| `chip` | `#EEF2FB` | 요약칩 · 존 배경 · 표 짝수행 |
| `amber` | `#F2A900` | 마커 · 강조 채움 · 연결 화살표 |
| `amber_dk` | `#B57F00` | 앰버 계열 텍스트가 꼭 필요할 때 |
| `amber_wash` | `#FDF3DC` | 하단 '핵심' 존 배경 |
| `ink` | `#2B3440` | 본문 글자 |
| `on_navy` | `#A9B0CE` | 네이비 배경 위 보조 글자 |

**지켜야 할 규칙**

- **앰버는 채움·마커 전용.** 흰 배경 위 본문 텍스트 색으로 쓰지 않는다(대비 2.0:1).
  앰버 위에 글자를 올려야 하면 글자는 `navy`.
- process 노드: `navy → navy_75 → navy_55 → navy_30` 계조, **마지막 노드만 앰버**(도착점).
- cards 상단 바: 같은 계조. 숫자 뱃지는 순서가 있을 때(`numbered=true`)만.
- compare: 좌 `navy`(흰 글씨) / 우 `amber`(네이비 글씨). 2색만 쓴다.

## 2. 슬라이드 폰트

```
Pretendard  (assets/fonts/ 에 TTF 가 있으면)  →  .pptx 에 임베드
맑은 고딕    (없으면 자동 폴백)
```

- 설치: `python tools/get_fonts.py` (setup 스크립트가 자동 실행). OFL, 상업 이용·임베드 허용.
- 저장소에는 커밋하지 않는다(`.gitignore: assets/fonts/`).
- **`a:ea` 를 반드시 함께 세팅한다.** python-pptx 의 `run.font.name` 은 `<a:latin>` 만
  건드리는데 PowerPoint 는 한글을 `<a:ea>` 폰트로 그린다. `core/pptx_font.apply_face()` 가
  latin/ea/cs 를 모두 세팅한다 — 이걸 빼면 지정한 폰트가 한글에 적용되지 않는다.
- 임베드하면 파일이 약 3MB 커진다. STEP 4 '회사 양식' 확장기에서 끌 수 있다.

## 3. 타이포 스케일 (`deck_builder.TYPE`)

| 역할 | pt | 웨이트 | 자간 | 행간 |
|---|---|---|---|---|
| kicker | 11 | SemiBold | +0.14em | — |
| cover title | 40 | Bold | −0.025em | 1.14 |
| section title | 32 | Bold | −0.02em | 1.18 |
| slide title | 28 | Bold | −0.02em | 1.16 |
| chip | 15 | SemiBold | — | 1.25 |
| **bullet** | **15** | Regular | — | **1.42** |
| card label / desc | 15.5 / 12.5 | SemiBold / Regular | — | 1.20 / 1.38 |
| table head / body | 12 / 11.5 | SemiBold / Regular | — | 1.30 |

## 5. 도형

- **반경은 '인치 단위 시각 반경'** 으로 지정한다. `_adj(radius_in, w, h)` 가 도형 크기에
  맞춰 `adj` 값을 계산하므로, 크기가 달라도 라운드가 눈에 같아 보인다.
  표준: 카드·노드·사진 `0.10"`, 칩·뱃지는 완전 알약(`pill=True`).
- **그림자는 사진·카드·비교 컬럼에만.** 칩·바탕 도형은 평면.
  (`_shadow(blur=0.14", dist=0.035", navy 12% alpha`)
- 표는 PowerPoint 기본 파랑 밴딩 스타일을 제거하고 셀 채움을 직접 지정한다
  (`tableStyleId` 삭제 + 헤더 navy / 짝수행 chip / 흰 1pt 셀 경계).

## 6. 오버플로 보호

긴 한글이 박스를 말없이 넘치던 문제를 막는다.

| 함수 | 쓰는 곳 |
|---|---|
| `_measure(text, pt)` | 근사 폭. 한글·전각 1.0em / 라틴 0.54em / 공백 0.28em |
| `_fit(lines, …)` | 여러 문단이 **한 박스에 쌓이는** 경우(불릿·비교·마무리) |
| `_fit_each(items, …)` | 항목마다 **자기 박스**가 있는 경우(목차·퀴즈 보기·표 셀) |
| `_trim_to_fit(…)` | 최소 크기에서도 안 들어가면 뒤에서부터 제외 + 경고 로그 |

둘을 섞어 쓰면 높이를 과대/과소 계산한다. 새 렌더러를 만들 때 어느 쪽인지 먼저 정할 것.

## 7. 슬라이드 타입 13종

`cover · section · photo · bullets · process · cards · compare · table ·
quiz · objectives · agenda · closing · stat`

- `quiz` — 문제(네이비 칩) + 보기 ①~④ 알약 + **정답 뱃지 우하단**(앰버)
- `objectives` — 대형 연번 `01/02/03` + 목표. 이미지 없음
- `agenda` — 2열 번호 목록, `active` 로 현재 구간 강조
- `closing` — 요약 / 다음 차시 / 과제 3블록
- `stat` — 대형 숫자 + 설명 (최대 3개)

타입 선택 규칙은 `deck_builder._ART_RULES` 와 `skills/slides/SKILL.md` **양쪽에** 있다.
한쪽만 고치면 LLM 이 모르는 타입을 내보내 `bullets` 로 폴백한다.

## 8. 이미지 파일명 규칙

외부에서 만든 이미지는 `05_합치기/assets/` 에 **슬라이드 번호**로 넣는다.
자동 수집한 사진은 `03_비주얼/assets/` 에 같은 규칙으로 보관된다(같은 스캐너로 읽는다).

```
005_합치기/assets/003.png       → 3번 슬라이드
                 07.jpg         → 7번 슬라이드
                 012_뇌구조.png  → 12번 슬라이드   (뒤 설명은 자유)
                 표지.png        → 무시 (숫자로 시작하지 않음)
```

합치기는 `03_비주얼/assets`(자동) 을 바탕에 깔고 `05_합치기/assets`(내 것) 으로 덮는다.
내 이미지만 넣으면 자동 사진이 전부 사라진 덱이 나온다 — 실제로 그런 버그가 있었다.

- 번호는 `_이미지프롬프트.json` 의 `"n"` 과 같다(1-based).
- 지원 확장자: `.png .jpg .jpeg .webp` (webp 는 PNG 로 자동 변환).
- 같은 번호가 여럿이면 파일명 사전순 마지막 하나를 쓰고 나머지를 리포트한다.
- **이미지가 실제로 올라가는 타입은 `photo` 와 `bullets` 뿐이다**
  (`deck_builder.PLACEABLE_TYPES`). `bullets` 슬라이드는 이미지가 들어오면 `photo` 로
  승격된다. 카드·프로세스·표 등 도형 레이아웃은 자리가 없어 건너뛰고, 몇 번이 건너뛰어졌는지
  UI 에 표시한다.

## 9. 앱(웹) 스카이블루 램프

`≥500 은 텍스트로 읽히는 밝기, ≤400 은 채움 전용` 으로 나눈다(괄호는 흰 배경 대비비).

```
--brand-wash  #EAF3FC   호버 배경 · 뱃지
--brand-soft  #BCDDF7   선택 배경
--sky-400     #4A9BE0   채움 전용            (2.98:1 — 텍스트 금지)
--sky-500     #1B74BE   링크 · 아이콘 · 포커스 (4.90:1)
--brand       #1668C1   액션 채움 · 활성      (5.55:1)
--brand2      #0E4E96   눌림 · 앵커           (8.18:1)
--brand-deep  #1E2761   덱 네이비와 동일 — 공유 앵커
--brand-rgb   22 104 193   반투명은 항상 rgb(var(--brand-rgb) / .xx)
```

상태색은 브랜드 색조와 분리한다: `--ok #0E7355` · `--warn #8A6A0F` · `--err #B03A2B` ·
`--idle #9AA0AA`.

**미완 상태에는 색을 주지 않는다.** 15주차 패널의 상태 점은 미완이면 무채색 링,
완료되면 브랜드 색이 채워진다 — *채워지는 것 자체가 진행 표시*라서 무엇이 남았는지
훑어보면 바로 보인다.

Bloom 차트(`core/viz.py BLOOM_SHADES`)도 순서값이므로 같은 단색 계조를 쓴다.

## 10. 목록은 패널(위층), 작업은 바탕(아래층)

이 앱의 셸은 `xam-local`(`D:\00work\260803-xam-lo`)에서 가져왔다. 3층 구조다.

```
Layer 0  .app          바탕   — 좌측 레일 + 작업 화면        z-index: auto
Layer 1  .panel-layer  패널   — 강좌·주차 목록, 워크스페이스   z-index: 40
Layer 2  .toast        토스트                                z-index: 90
```

**규칙**: 목록은 패널(고르는 곳), 작업은 바탕(하는 곳).

```
좌측 레일에서 '교재'·'슬라이드' 클릭
   ↓
패널      안쪽 레일 = 강좌 목록  /  본문 = 그 강좌의 15주차
   ↓ 칸 클릭
바탕      그 주차의 작업 화면으로 바뀌고 패널이 닫힌다
```

라우터는 2층 해시 라우터(`static/js/shell.js`)다. 라우트마다 `layer: "base" | "panel"` 을
선언하고, 패널을 열어도 `#view`(바탕)는 언마운트되지 않는다. **그게 이 구조의 존재 이유다** —
생성이 몇 분 걸리는 SSE 스트림이 진행 중이고 편집기에 미저장 텍스트가 있어도 그 위로 목록을
열 수 있다.

그 대가로 지켜야 할 규칙: **미저장 텍스트를 든 화면을 패널에 두지 않는다.** 패널은 Esc·스크림
클릭으로 닫히므로 편집이 날아간다. 그래서 워크스페이스의 폼은 저장 버튼이 명시적이다.

구현 세부(`static/js/panel.js`):
- `role="dialog" aria-modal="true"`, 바탕 전체에 **`inert`** 부여.
  Tab 트랩을 손으로 짜지 않는다 — Chrome 은 `tabindex` 없는 스크롤 div 에도 포커스를 주므로
  "마지막 포커스 가능 요소"를 신뢰성 있게 계산할 수 없다.
- 닫을 때 **`inert` 를 먼저 벗기고** 포커스를 복원한다(순서가 바뀌면 복원이 먹지 않는다).
- 닫기는 직접 닫지 않고 셸에 위임해 바탕 라우트로 되돌린다. `history.back()` 을 쓰면
  안 된다 — 안쪽 레일로 옮겨 다녔다면 바로 이전 기록도 또 다른 패널이라서, 닫히는 대신
  한 칸 되돌아간 것처럼 보인다.
- 이미 열려 있으면 내용만 갈아 끼운다(rise 애니메이션을 다시 재생하지 않는다).

생성 중에는 주차 전환 버튼이 잠긴다(`weekbar.setBusy`).

### 좌하단 칩 = 워크스페이스
강좌 전환 · 강의 기본 정보 · LiteLLM 연결 설정 · 슬라이드 양식이 전부 이 패널 하나에 있다.
이 값들은 "작업"이 아니라 "설정"이라 바탕을 차지할 이유가 없고, 서로 붙어 있어야 한 번에
점검된다(키가 없어서 생성이 안 되는데 폼만 붙들고 있는 상황이 실제로 잦았다).

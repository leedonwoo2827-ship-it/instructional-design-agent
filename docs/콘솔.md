# 교수설계 가이드 에이전트

강의 정보를 입력하면 **강의계획서 → 교재 → 디자인된 슬라이드(.pptx)** 를 만들고, 실무 기준에 맞춰
**정렬 점검·직접 편집**까지 하는 로컬 콘솔입니다. 산출물은 강좌·주차 단위로 폴더에 전부 남습니다.

사내 **Ubion LiteLLM 프록시**(OpenAI 호환)를 사용하며, URL·API 키·모델은 **좌하단 워크스페이스 › 연결 설정**에서 입력합니다.

## 요구사항
- Python 3.10 ~ 3.13
- 사내망 접속 (LiteLLM 프록시 `192.168.50.119:4000` 도달 가능)
- 본인 LiteLLM virtual key (`sk-...`) — 사내 대시보드 `/ui/` 에서 발급

## 설치 & 실행 (Windows)
1. **`setup.bat`** 더블클릭 — `.venv` 생성, 의존성 설치, `.env` 준비, 슬라이드 폰트 설치
2. **`run.bat`** 더블클릭 — 브라우저에서 `http://localhost:8701` 열림
3. **좌하단 워크스페이스 칩** → **연결 설정** 에 `sk-` 키 입력 → 저장
4. **강좌** 에서 새 강좌 만들기 → **강의 기본 정보** 입력 → 좌측 레일 **강의계획서** → 생성

macOS / Linux: `./setup.sh` 후 `./run.sh`.

## 화면 구조 — 목록은 패널(위층), 작업은 바탕(아래층)

```
┌─ 좌측 레일 ──────┬─ 바탕(작업 화면) ─────────────────┐
│ 교수설계 에이전트 │                                   │
│ [다음 미작성 주차]│   무엇을 할까요 / 강의계획서 /     │
│ · 강의계획서      │   교재 / 슬라이드                 │
│ ─────────────    │                                   │
│ · 교재    주차별  │        ┌─ 패널(위층) ─────┐       │
│ · 슬라이드 주차별 │        │ 강좌 │ 15주차 목록 │       │
│                  │        └──────────────────┘       │
│ 최근 강좌         │         칸 클릭 → 패널 닫히고     │
│ [워크스페이스 칩] │         바탕이 그 주차로 바뀜      │
└──────────────────┴───────────────────────────────────┘
```

- **좌측 레일**: 단계 메뉴. `강의계획서`는 강좌 전체 단계라 바로 열리고, `교재`·`슬라이드`는
  **주차 단위**라 먼저 목록 패널이 뜹니다.
- **패널**: 안쪽 레일 = 강좌 목록, 본문 = 그 강좌의 15주차. 패널을 열어도 **바탕은 유지**되므로
  생성이 진행 중이거나 편집하던 내용을 잃지 않습니다.
- **좌하단 워크스페이스 칩**: 강좌 전환 · 강의 기본 정보 · **LiteLLM 연결 설정** · 슬라이드 양식.
- **`다음 미작성 주차`**: 어느 화면에 있어도 아직 덱이 없는 주차로 한 번에 이동합니다.

## 사용 흐름

| 화면 | 내용 |
|---|---|
| **강의계획서** | 강의 기본 정보 → 생성(스트리밍) → **정렬 점검**(실무형 기준 감사, ✅/⚠️/❌ 수정 제안을 문서 하단에 덧붙임) → 수정 요청 · 직접 편집 |
| **교재** | 주차 선택 → 학생용 읽기 자료 생성. 확인 · 수정 · 점검 · 직접 편집 |
| **슬라이드** | 아래 **5단계 파이프라인** |

### 슬라이드 5단계

각 단계가 자기 폴더에 산출물을 남기고, 단계마다 버전이 따로 쌓입니다. 한 단계만 다시
돌릴 수 있습니다 — 사진만 다시 받거나 프롬프트만 다시 뽑는 게 됩니다.

| # | 단계 | 하는 일 | 남는 곳 | LLM |
|---|---|---|---|---|
| 1 | **개요** | 제목 목록 → 상세 개요 (시간당 20장) | `01_개요/슬라이드개요.md` | ✓ |
| 2 | **초안 PPT** | 레이아웃 13종 배정 → 사진 없이 빌드 | `02_초안/슬라이드플랜.json` · `슬라이드_v1.pptx` | ✓ |
| 3 | **사진원고 서칭/추가** | 주제 사진 수집·배치 → 재빌드 · **꺼 둠**(`week-ppt.js` 의 `off`) | `03_비주얼/assets/` · `슬라이드_v1.pptx` | — |
| 4 | **씬 프롬프트 생성** | 슬라이드(씬)별 이미지 생성 프롬프트 | `04_씬프롬프트/이미지프롬프트.json` | ✓ |
| 5 | **이미지 합치기 및 최종 PPTX** | 만들어 온 이미지 삽입 → 최종본 | `05_합치기/assets/` · `슬라이드_v1.pptx` | — |

슬라이드 레이아웃 13종: `표지 · 섹션 · 사진 · 불릿 · 프로세스 · 카드 · 비교 · 표 ·
퀴즈(정답 우하단) · 학습목표 · 목차 · 마무리 · 수치`

## 산출물 보관 — 폴더가 파이프라인과 1:1

주차를 오가도 덮어써지지 않고, 어느 단계 산출물인지 경로만 봐도 알 수 있습니다.

```
workspace/01_교육방법및교육공학/
  project.json                     강좌 메타(이름·주차수·강의 정보)
  00_강의계획서/강의계획서.md        ← 강좌 루트
  03/                              ← 3주차
    00_교재/         교재.md · 대화.json
    01_개요/         슬라이드개요.md · 대화.json
    02_초안/         슬라이드플랜.json · 슬라이드_v1.pptx …
    03_비주얼/       assets/(수집 사진) · 이미지출처.txt · 슬라이드_v1.pptx …
    04_씬프롬프트/   이미지프롬프트.json
    05_합치기/       assets/(내가 만든 이미지) · 슬라이드_v1.pptx …
  01/ 02/ … 15/
```

- 단계마다 버전 계열이 따로입니다. `02_초안/슬라이드_v2.pptx` 는 초안을 두 번 설계했다는
  뜻이고, `05_합치기/슬라이드_v3.pptx` 는 이미지를 세 번 합쳤다는 뜻입니다.
- 이미지 파일명 규칙: `003.png` → 3번 슬라이드. 확장자·뒤 설명은 자유(`003_뇌구조.png`).
  번호는 `이미지프롬프트.json` 의 `"n"` 과 같습니다.
- **합치기는 자동 사진 위에 내 이미지를 덮습니다.** 자동 수집한 사진은 `03_비주얼/assets/`
  에 보관되므로 재빌드해도 사라지지 않습니다.
- 이미지가 실제로 올라가는 슬라이드는 `사진`·`불릿` 타입뿐입니다. 카드·프로세스·표처럼 도형이
  자리를 다 쓰는 레이아웃은 건너뛰고, 몇 번이 건너뛰어졌는지 화면에 표시합니다.
- 파일이 source of truth 입니다. 강좌를 목록에서 지워도 폴더는 남고, 워크스페이스의
  **폴더에만 남은 강좌**에서 되살리거나 완전히 지울 수 있습니다.

## 슬라이드 폰트
**Pretendard**(OFL, 상업 이용 무료)를 쓰고 **.pptx 에 임베드**하므로 폰트가 없는 PC 에서도
레이아웃이 그대로 열립니다. `setup` 이 자동 설치하고, 수동 설치는 `python tools/get_fonts.py`.
폰트가 없으면 `맑은 고딕`으로 자동 폴백합니다. 색·타이포 규칙은 [docs/디자인-토큰.md](docs/디자인-토큰.md).

> python-pptx 의 `font.name` 은 `<a:latin>` 만 세팅하는데 PowerPoint 는 한글을 `<a:ea>` 로
> 그립니다. `core/pptx_font.py` 가 latin/ea/cs 를 함께 세팅합니다 — 이게 없으면 지정한 폰트가
> 정작 한글에는 적용되지 않습니다.

## 모델
워크스페이스 › 연결 설정에서 선택 (기본 **`deepseek-v4-flash-think`**):
- DeepSeek V4 — `deepseek-v4-flash` / `deepseek-v4-flash-think`(추론) / `deepseek-v4-pro`
- Claude — `claude-sonnet-4-6`(균형) / `claude-opus-4-7`(고품질) / `claude-haiku-4-5`(빠름)

> 슬라이드 디자인(②)의 구조화(JSON) 작업은 추론 모델이 형식을 깨뜨리므로 **비추론 모델을 자동 사용**합니다.
> 추론(-think) 모델은 아주 긴 산출물(교재 등)에서 출력이 잘릴 수 있습니다.

## 프롬프트 관리 (skills/)
프롬프트는 코드가 아니라 [skills/](skills/) 의 `SKILL.md` 로 관리합니다. 첨삭이 오면 해당 스킬 파일을
편집하고 서버를 재시작하면 반영됩니다. [skills/README.md](skills/README.md) · [docs/첨삭-로그.md](docs/첨삭-로그.md).

## 보안
- API 키·강좌 DB·회사 양식·주차별 산출물·원본 첨삭 자료는 **`.gitignore` 로 커밋에서 제외**됩니다
  (`.env`, `data/user_settings.json`, `data/app.db`, `assets/*.pptx`, `assets/fonts/`,
  `static/fonts/`, `workspace/`, `_context/`, `_assets/`, `_guideline/`).
- 서버는 `127.0.0.1` 에만 바인딩합니다(로컬 전용).

## 설정 우선순위
`data/user_settings.json`(워크스페이스 저장값) > `.env` 환경변수 > 코드 기본값

### 산출물을 저장소 밖에 두기
주차별 산출물을 다른 드라이브·폴더에 모으려면 `.env` 에 절대경로를 지정합니다.
비우면 저장소 안의 `workspace/` 를 씁니다. **어느 쪽이든 커밋에는 포함되지 않습니다.**

```
IDA_WORKSPACE=D:\00work\_산출물\교수설계
IDA_DB_PATH=D:\00work\_산출물\교수설계\app.db      # 선택
```

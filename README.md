# 이론강의 영상 자동 생성

강의계획서 → 교재 → 슬라이드 → **나레이션 강의 영상**. 로컬 전용, API 키 없음.

```
setup.bat   (최초 1회)
run.bat     →  http://localhost:8701
```

---

## 이렇게 씁니다

왼쪽 메뉴를 위에서 아래로 따라가면 됩니다. 각 단계는 **파일로 남으니** 중간에 멈췄다가
다시 해도 되고, 마음에 안 드는 단계만 다시 돌려도 됩니다.

```
강의계획서  →  교재  →  슬라이드 (5단계)  →  영상 (2단계)
   강좌 전체      주차별        주차별            주차별
```

### 슬라이드 5단계

| | 단계 | 무엇을 하나 |
|---|---|---|
| ① | 개요 | 강의계획서의 그 주차 목표를 물려받아 **슬라이드 목록과 내용**을 글로 씁니다 |
| ② | 초안 PPT | 개요를 읽어 슬라이드마다 **모양을 정하고** 사진 없이 먼저 PPT를 만듭니다 |
| ③ | 비주얼 정돈 | 사진이 필요한 슬라이드에 **인터넷에서 무료 사진을 찾아** 넣습니다 |
| ④ | 씬 프롬프트 | 사진을 **못 찾은 자리**만 골라, 그림 생성용 주문서(영어)를 뽑아 줍니다 |
| ⑤ | 이미지 합치기 | 직접 만들어 온 그림을 폴더에 넣으면 PPT에 **끼워 넣고** 다시 만듭니다 |

**③ 에서 `사진 7/26` 처럼 보이는 숫자**는 "사진이 들어갈 자리 26곳 중 7곳을 찾았다"는 뜻입니다.
찾지 못하는 건 검색어에 맞는 무료 사진이 없어서입니다 — 정상입니다.

**④ 는 못 찾은 것만 뽑습니다.** 위 예라면 26 − 7 = **19개**가 나옵니다.
이미 사진이 있는 7곳은 다시 그릴 필요가 없으니까요.

**⑤ 에 그림을 넣는 방법** — 파일 이름을 **슬라이드 번호**로 저장하면 됩니다.
`006.png` 는 6번 슬라이드로 갑니다. 앞 숫자만 맞으면 뒷말은 자유입니다(`006_뇌구조.png`).
넣을 폴더는 화면에 경로가 적혀 있고 `이미지 폴더 열기` 버튼으로 바로 열립니다.

### 영상 2단계

| | 단계 | 무엇을 하나 |
|---|---|---|
| ① | 나레이션 대본 | 슬라이드를 읽어 **말할 내용**을 씁니다. 화면에서 고칠 수 있습니다 |
| ② | 영상 렌더 | 슬라이드를 그림으로 뽑고 **목소리와 자막**을 붙여 mp4로 만듭니다 |

**② 는 오래 걸립니다** — 100분 영상이면 1시간 넘습니다.
**창을 닫아도 계속 만들어집니다.** 나중에 다시 열어보면 진행률이 그대로 보입니다.

### 대본을 종이로 확인받기

① 에서 **`인쇄 (강사 확정용)`** 버튼을 누르면 새 창에 확인용 문서가 뜹니다.
그 창에서 인쇄하고, 대상을 `PDF로 저장` 으로 고르면 PDF 로 받습니다.

- **슬라이드가 왼쪽에 작게, 대본이 오른쪽에** — 어느 화면의 말인지 보입니다
- 씬마다 **시간대**(`55:58 ~ 57:11`)가 적혀 있습니다
- 씬마다 `☐확인 ☐수정 필요` 와 메모 여백이 있습니다

영상을 만들기 **전에도** 됩니다. 아직 안 만들었으면 슬라이드 그림만 먼저 뽑고(약 10초)
시간은 글자수로 추정해 적습니다 — 문서에 `추정` 이라고 표시됩니다.
영상을 이미 만들었으면 **실제 음성 길이**로 적습니다.

> 순서: 사진을 채우고 → **강사 확정** → 영상 렌더.
> 대본은 그 전에 뽑아도 되지만, 영상은 확정 뒤에 만듭니다.

### 자주 궁금해하는 것

**사진이 왜 전부 안 들어가나요**
표·순서도·비교표처럼 **그림 자체가 정보인 슬라이드**에는 사진 자리가 없습니다.
사진은 설명형 슬라이드에만 들어가고, 전체의 약 절반입니다.

**슬라이드가 왜 80장인가요**
영상 길이에서 거꾸로 계산합니다. 한 장을 약 **1분 15초** 설명하므로 100분이면 80장입니다.
실습이 있는 주차는 목표 시간을 줄이면 장수도 같이 줄어듭니다.

**첫 글자가 안 나와요**
글을 쓰기 시작하기까지 **8~10초** 걸립니다. 그동안은 커서만 깜빡입니다. 정상입니다.

**[입력 필요] 라고 적혀 있어요**
학기·강의실·연락처처럼 알려 드리지 않은 정보는 지어내지 않고 비워 둡니다. 직접 채우시면 됩니다.

## 무엇이 어디에 있나

저장소는 하나이고, 가상환경만 둘이다.

```
260804-ppt2eduvideo\            ← 저장소 하나. setup.bat · run.bat 이 여기 있다
├─ setup.bat  run.bat           최초 1회 / 실행
├─ .venv\                       영상 엔진   (onnxruntime · pywin32 · soundfile)
├─ .venv-app\                   교수설계 콘솔 (fastapi · openai)
│
├─ server.py  static\           콘솔 화면과 API (FastAPI + 정적 프런트)
├─ core\                        workspace · llm · deck_builder · video · prompts …
├─ skills\                      SKILL.md 프롬프트 (syllabus · slides · narration …)
├─ docs\                        디자인 토큰 · 첨삭 로그 · 콘솔 설명
├─ assets\                      회사 PPT 양식 · 로고 · 폰트 (git 제외)
├─ data\                        런타임 — app.db · user_settings.json (git 제외)
│
├─ backend\                     엔진: 추출 · PNG 렌더 · 번들 · 렌더 실행
├─ scripts\                     doctor.py · run_job.py · make_viewer.py · build_video.py
└─ vendor\chodangi\             TTS · 자막 · ffmpeg 합성 (수정하지 않는다)
   └─ assets\                   Supertonic 3 모델 383MB (git 제외 · 별도 배포)
```

가상환경만 둘이고 저장소는 하나다. 콘솔이 엔진을 `subprocess` 로 부른다.

**의존성을 섞지 않는 이유**가 이 구조의 전부다:

1. `onnxruntime` 이 콘솔 쪽 의존성과 충돌한다
2. PowerPoint COM 은 스레드마다 `CoInitialize` 가 필요하고 인스턴스가 하나뿐 — 별 프로세스여야 안전하다
3. **콘솔을 닫아도 렌더가 계속된다.** 100분 영상은 1시간이 넘는다

콘솔은 엔진을 `subprocess` 로 부르고 `progress.json` 만 읽는다. 파일로만 대화한다.

## LLM 은 Claude Code CLI (구독 인증)

**API 키를 발급하지 않는다.** 이 PC 의 Claude Code 로그인을 그대로 쓴다
(`core/llm.py` 의 `ClaudeCliProvider` → `claude -p`).

사내 LiteLLM 프록시도 남겨 뒀다. **워크스페이스 → 연결 설정**에서 고른다:

| 방식 | 필요한 것 |
|---|---|
| `cli` (기본) | Claude Code 로그인만. 키·URL 없음 |
| `litellm` | 프록시 URL + `sk-` 키 |

스트리밍은 `--output-format stream-json` 으로 증분 텍스트를 받는다(타이핑 효과 유지).
구조화(JSON) 작업은 형식 안정성 때문에 비추론 모델을 자동으로 쓴다.

## 영상 길이 = 슬라이드 학습 시간

**이 프로젝트에서 가장 틀리기 쉬운 부분이다.**

| | 값 |
|---|---|
| 기준 | **2.5분/슬라이드** — 20장 = 50분, 40장 = 100분 |
| 실측 발화 속도 | **7.53자/초** (Supertonic F2 · speed 1.02) |
| 슬라이드당 대본 | **약 1,100자 / 12~18문장** |
| 렌더 시간 | 19분 영상 = 14분 → 100분이면 약 75분 |

목표 분을 주면 `core/video.py` 가 슬라이드 유형 가중치로 목표 글자수를 배분하고
(섹션 표지는 0.35배), 생성 후 글자수를 재서 **목표의 85% 미만인 슬라이드만 보강 재요청**한다.

> 분량을 프롬프트에만 맡기면 반드시 짧게 나온다. 초기 버전이 **목표의 1/8**(18초/장)이었다.
> 그래서 측정하고 되먹인다. 8장/20분 실측: 9,964자 → 예상 22.1분 (목표 대비 +10%).

목표 분은 STEP 1 의 `video_minutes` 로 넣거나 영상 화면에서 직접 바꾼다.
실습·토론이 있는 주차는 그만큼 줄이면 슬라이드 장수도 따라 줄어든다.

## 대본은 버튼 한 번으로 끝나지 않는다

40장 × 1,100자 = 약 44,000자. 버튼은 **초안**을 만든다.

```
02_초안\슬라이드플랜.json ──[콘솔: 대본 생성]──► 06_영상\나레이션.json
                                                    │
                              [Claude Code 창에서 다듬기]  ← 실제 시간은 여기서 쓴다
                                                    ▼
                                              06_영상\나레이션.json
                                                    │
                                     [콘솔: 검수 · 렌더]
                                                    ▼
                                              완성\영상_v1.mp4
```

`나레이션.json` 하나가 유일한 진실이다. 콘솔을 닫아도 무관하다.
두 쪽이 같은 파일을 쓰므로 저장은 **원자적 + `.bak`**, 내용이 같으면 쓰지 않는다.

## 절대 건드리면 안 되는 것

**`CROSSFADE_SEC = 0.6`** (`backend/config.py`) — 씬 경계에서 겹치는 초.
TTS(자막 타임코드)와 mp4maker(실제 합성)가 **같은 값**을 써야 한다.
어긋나면 자막이 씬마다 누적으로 밀린다 — 원본 프로젝트에서 46씬 영상이 **83.6초** 밀렸다.

```
씬 N 시작 = sum(dur[0..N-1]) - N × crossfade
총 길이   = sum(dur) - (N-1) × crossfade
```

회귀 검증: 씬 40개 이상에서 위 식이 성립하고 마지막 자막 큐가 총 길이와 맞는지 본다.
(8씬 실측: 예상 1136.02s / 실제 1136.15s / 오차 **0.13초**)

약어·전공 영어는 그대로 읽으면 이상해진다. `vendor/chodangi/config/pronunciation_map.yaml`
이 합성 **직전에** 치환한다(자막에는 적용하지 않는다 — 자막은 원문이 맞다).

Gagne: 가네

무엇이 바뀌었는지는 `06_영상\bundle.html` 의 **발음** 카드에서 확인한다.
mtime 핫리로드라 파일만 고치고 그 씬만 다시 합성하면 반영된다.

## 밖에 남는 것

내장할 수 없는 것만 남는다. `setup.bat` 과 `doctor.py` 가 전부 확인한다.

| 무엇 | 왜 못 넣나 | 없으면 |
|---|---|---|
| `ffmpeg` · `ffprobe` (PATH) | 바이너리 | TTS 를 몇 분 돌린 뒤 **마지막 합성에서** 실패 |
| PowerPoint | 상용 SW | 슬라이드 PNG 를 못 만든다 |
| Claude Code 로그인 | OAuth 세션 | 대본·개요 생성 실패 |
| `vendor\chodangi\assets\` 383MB | 용량 (git 제외) | Supertonic 이 아예 로드되지 않는다 |
